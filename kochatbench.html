KoChatBench: A Korean Multi-turn Chatbot Benchmark for Conversational Capability Evaluation

Cheonsol Lee, Hyeonwoo Kim

A capability-based benchmark for diagnosing Korean multi-turn dialogue failures

Motivation

  • Real chatbot use spans three or more turns, requiring models to retain prior information, resolve ellipsis and anaphora, and handle topic shifts — but most LLM evaluation is still single-turn or English-centric.
  • Korean dialogue adds language-specific failure modes: subject omission, demonstratives, particles, honorifics, and style shifts are tightly coupled to context in ways that simply translating English benchmarks does not capture.
  • Existing multi-turn benchmarks (MT-Bench-101, MultiChallenge, TOD-ProcBench, …) are large but not built around Korean-specific capabilities.

Building the Benchmark

  • Sessions are generated against a taxonomy of four core capabilities: context & reference management, instruction constraint maintenance & response execution, revision & recovery, and dialogue recovery & robustness — each split into mutually exclusive sub-tasks.
  • GPT-5.5 and Claude Sonnet 4.6 generate candidate sessions; rule-based checks catch structural errors, then the same models judge consistency and naturalness before rejected samples are regenerated and accepted ones human-verified.

How Tasks Are Defined & Scored

Each of the 12 tasks has its own English-language rubric with four scoring bands (1–10 scale) — the judge sees only the rubric for the task being tested, and scores the final assistant turn against it.

Worked example — C1-03 · Referential & Ellipsis Resolution

ScoreCriterion
1–3Resolves the reference to the wrong entity, or cannot answer.
4–6Resolves some references but misses or confuses key links.

The session opens with a user listing three items by name (가방/bag, 코트/coat, 운동화/sneakers, each with a price), then a fourth, unrelated item (지갑/wallet) enters the conversation. Every question after that points at an item only through a chain of position and discourse references — never the item's name — so the assistant has to keep resolving each new pronoun against what it just said, not against the original list:

User

어제 백화점에서 가방, 코트, 운동화를 차례로 봤어. 가방은 18만 원, 코트는 24만 원, 운동화는 13만 원이었어. 셋 다 마음에 들긴 했어.

Assistant (context)

세 가지를 차례로 보셨군요. 가격대가 조금씩 다르니 어디에 더 끌리는지부터 정하면 고르기 쉬워질 거예요.

User

점심 먹고 지갑도 봤는데 그건 30만 원이라 바로 포기했어. 방금 본 지갑 말고, 아까 백화점에서 차례로 본 것 중 두 번째로 말한 거, 그거 가격이 얼마였는지 다시 알려줘.

방금 말한 그것 바로 앞에 봤던 게 사실 제일 끌려. 그건 얼마였는지 짚어줘.

Gemma-4-31B-IT answered코트 바로 앞에 보신 것은 가방이며, 가격은 18만 원이었습니다.

"그것 바로 앞에" ("the one right before that") only resolves correctly if the model still has the previous answer's referent (코트/coat) live in working memory — not the original user list. It does, across all three consecutive indirect references in this session, and the LLM-as-a-judge scores each one 10/10 against the golden answer above. (Run: v2_pilot2, target google/gemma-4-31b-it, judge gpt-5.4-mini.)

Results

Six commercial LLMs were evaluated with session-level minimum scoring (0–100) — a single bad turn drags down the whole session, which is deliberate: it surfaces stability failures that a mean-only score would hide.

ModelOverall
Gemma-4 31B-it91.0

Nemotron Super71.6
  • Gemma-4-31B-IT leads overall but is not universally best — it records the lowest score among all models on the Explicit Information Recall sub-task, showing that a strong aggregate can still hide task-specific weaknesses.
  • Nemotron-3-Super-120B-A12B shows the weakest overall performance, concentrated in Conversational Recovery & Robustness — trouble preventing error propagation, resolving ambiguity, and resuming topic after interruptions.
  • Scores are consistently lower on later turns, indicating that context degrades before it fully breaks — a pattern only visible because KoChatBench scores every turn, not just the final one.

Ongoing work: the KoChatBench evaluation suite is under active development in a private repository — the v2 pilot (117 samples across 12 tasks) is currently benchmarking Gemma-4-31B-IT, GPT-OSS-120B, and GPT-OSS-20B, extending the capability-level analysis introduced in the paper.
